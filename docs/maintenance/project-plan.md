# 项目实施方案

## 目标

建立中文开发工具知识库，以 OMP 跑通官方变化检测、更新建议、审核和发布。
使用 Markdown、Python、GitHub Actions、PR 与 MkDocs。

通用教程放入本仓库；项目专属约定和可执行脚本保留在原仓库。
同一份教程维护一个主要版本，其余位置链接引用。

## 流程与状态

定时采集 → 比较已合并基线 → 生成报告与摘要 → 校验候选 →
创建或更新 PR → 人工审核与必要实测 → 合并接受基线 → 发布。

稳定版与开发分支分别比较。首次来源登记、人工审核、命令实测分别记录。
候选 PR 未合并前不会成为主分支的已接受基线。

## 交付

- OMP 安装、PowerShell、字体主题、排错和来源更新记录。
- 来源配置、不可变采集、发布分页和差异报告。
- 规则摘要及可选 AI 证据草稿。
- PR 去重、人工提交保护和失败汇总。
- 文档边界、内部链接、元数据检查、单元测试、严格构建。
- 每日更新、周度外链检查与网站发布。

## 验收

1. 分别发现版本更新和仅文档变化。
2. 覆盖多个版本、预发布版过滤、基线缺失和来源失败。
3. 保护个人区域，不将检测标记为实测。
4. 相同输入不重复建 PR，关闭候选不推进基线。
5. 人工修改或并发更新自动分支时停止覆盖。
6. 候选检查失败不发布；AI 失败仍生成基础报告。
7. 网站构建失败保留上一成功版本。

## 费用与边界

定时任务不是严格准点服务。费用取决于账户额度、运行量和 AI 服务。
AI 默认关闭；每个新候选最多请求一次，限制输入输出。
先接入 OMP，稳定后扩展。非 GitHub Releases 或跨仓库文档需扩展来源适配。
